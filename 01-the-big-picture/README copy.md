# ⚙️ Abstraction

مهم‌ترین مفهومی که این فصل روی آن تأکید می‌کند **Abstraction** است.

**Abstraction** یعنی برای فهم یک سیستم پیچیده، لازم نیست تمام جزئیات آن را بدانیم. کافی است ابتدا نقش هر بخش را بشناسیم و بعد، در صورت نیاز، به لایه‌های عمیق‌تر برویم.

### 🚗 یک مثال ساده

فرض کنید می‌خواهید رانندگی کنید.

لازم نیست بدانید موتور خودرو دقیقاً چگونه کار می‌کند یا جعبه‌دنده چه مکانیزمی دارد. کافی است بدانید:

* فرمان → جهت حرکت را کنترل می‌کند.
* گاز → سرعت را افزایش می‌دهد.
* ترمز → سرعت را کاهش می‌دهد.

اما اگر خودرو دچار مشکل شود، آن‌وقت باید قدم‌به‌قدم به بخش‌های داخلی نزدیک‌تر شوید تا علت را پیدا کنید.

**لینوکس هم دقیقاً با همین دیدگاه قابل درک است.**

در سطح بالا، یک سیستم لینوکسی از سه بخش اصلی تشکیل شده است:

```text
┌───────────────────────────────────────┐
│              User Space               │
│                                       │
│  Browser · Database · Web Server      │
│  Terminal · Applications · ...        │
└───────────────────┬───────────────────┘
                    │
              System Calls
                    │
┌───────────────────▼───────────────────┐
│                Kernel                 │
│                                       │
│  Process · Memory · Devices · Files  │
│  Networking · System Calls · ...     │
└───────────────────┬───────────────────┘
                    │
┌───────────────────▼───────────────────┐
│               Hardware                │
│                                       │
│    CPU · RAM · Disk · Network Card    │
└───────────────────────────────────────┘
```

### 🔹 Hardware

تمام سخت‌افزار سیستم؛ از **CPU** و حافظه اصلی (**RAM**) گرفته تا **Disk** و **Network Card**.

### 🔹 Kernel

هسته سیستم‌عامل که واسطه میان نرم‌افزار و سخت‌افزار است.

Kernel مدیریت مواردی مانند:

* پردازنده
* حافظه
* دستگاه‌ها
* و ارتباط برنامه‌ها با سخت‌افزار

را بر عهده دارد.

### 🔹 User Space

تمام برنامه‌هایی که ما روزانه با آن‌ها کار می‌کنیم؛ مانند:

* Browser
* Database
* Web Server
* Terminal
* و صدها برنامه دیگر

---

# ⚙️ Kernel Mode vs User Mode

یکی از مهم‌ترین نکات این فصل، تفاوت بین **Kernel Mode** و **User Mode** است.

سیستم برای جلوگیری از دسترسی کنترل‌نشده برنامه‌ها به منابع حساس، اجرای کد را به سطوح مختلف دسترسی تقسیم می‌کند.

### 🔴 Kernel Mode

کدی که داخل **Kernel Mode** اجرا می‌شود، دسترسی بسیار گسترده‌ای به منابع سیستم، حافظه و پردازنده دارد.

به همین دلیل اگر در کرنل خطایی رخ دهد، ممکن است **کل سیستم از کار بیفتد**.

### 🟢 User Mode

برنامه‌های عادی در **User Mode** اجرا می‌شوند.

هر Process فضای حافظه مخصوص خود را دارد و اگر دچار **Crash** شود، معمولاً سایر بخش‌های سیستم تحت تأثیر قرار نمی‌گیرند.

### 🔐 چرا این جداسازی مهم است؟

این جداسازی یکی از پایه‌های:

* **Stability**
* **Security**
* **Isolation**

در سیستم‌عامل است.

به‌صورت ساده:

```text
                 ┌──────────────────────┐
                 │      User Space      │
                 │                      │
                 │ Browser              │
                 │ Database             │
                 │ Terminal             │
                 │ Web Server           │
                 └──────────┬───────────┘
                            │
                       System Call
                            │
                 ┌──────────▼───────────┐
                 │        Kernel        │
                 │                      │
                 │ Process Management   │
                 │ Memory Management    │
                 │ Device Drivers       │
                 │ File Systems         │
                 └──────────┬───────────┘
                            │
                 ┌──────────▼───────────┐
                 │       Hardware       │
                 └──────────────────────┘
```

# ⚙️ The Four Main Responsibilities of the Kernel

Kernel وظایف بسیار زیادی دارد، اما در تصویر کلی می‌توان چهار مسئولیت اصلی برای آن در نظر گرفت:

### 1. 🧵 Process Management

مدیریت **Process**ها و زمان‌بندی اجرای آن‌ها.

### 2. 🧠 Memory Management

مدیریت **Memory** و تخصیص منابع حافظه به Processها.

### 3. 🔌 Device Drivers

مدیریت **Device Driver**ها و ارتباط با سخت‌افزار.

### 4. 📞 System Calls

ارائه **System Call**ها برای ارتباط برنامه‌ها با Kernel.

---

در واقع هر بار که یک برنامه بخواهد:

* فایلی را باز کند،
* داده‌ای روی دیسک بنویسد،
* از شبکه استفاده کند،
* حافظه‌ای درخواست کند،
* یا با یک Device کار کند،

مستقیماً با سخت‌افزار صحبت نمی‌کند.

بلکه از طریق **System Call** از Kernel درخواست انجام این کار را می‌کند.

```text
Application
     │
     │ System Call
     ▼
  Kernel
     │
     ▼
Hardware
```

---

# ⚙️ System Call

**System Call** مکانیزمی است که برنامه‌های User Space از طریق آن از Kernel درخواست سرویس می‌کنند.

دو مورد از مهم‌ترین System Callها:

* `fork()`
* `exec()`

هستند.

---

## `fork()`

`fork()` یک **کپی تقریباً یکسان از یک Process** می‌سازد.

به Process اصلی معمولاً **Parent Process** و Process جدید **Child Process** گفته می‌شود.

```text
Parent Process
      │
    fork()
      │
      ├──────────────► Parent
      │
      └──────────────► Child
```

---

## `exec()`

`exec()` یک برنامه جدید را بارگذاری کرده و جایگزین برنامه‌ای می‌کند که در Process در حال اجرا بوده است.

به بیان ساده:

```text
Existing Process
       │
      exec()
       │
       ▼
New Program
```

نکته مهم این است که `exec()` معمولاً **Process جدیدی ایجاد نمی‌کند**؛ بلکه برنامه‌ای که در Process اجرا می‌شود را با برنامه جدید جایگزین می‌کند.

---

## 🖥️ مثال: اجرای `ls`

مثلاً وقتی دستور `ls` را در ترمینال می‌زنید، Shell می‌تواند از `fork()` استفاده کند تا یک Process جدید ایجاد شود و سپس آن Process با `exec()` برنامه `ls` را اجرا کند.

به‌صورت ساده:

```text
Shell
 │
 │ fork()
 ▼
Child Process
 │
 │ exec()
 ▼
ls
```

تقریباً تمام Processهای یک سیستم لینوکسی به شکل‌های مختلف از همین مدل **ایجاد Process و اجرای برنامه** استفاده می‌کنند.

---

# ⚙️ Context Switch

نکته جالب دیگر، نحوه اجرای هم‌زمان برنامه‌هاست.

وقتی چندین برنامه را هم‌زمان باز می‌کنید، به نظر می‌رسد همه آن‌ها هم‌زمان در حال اجرا هستند.

اما روی یک پردازنده تک‌هسته‌ای، در هر لحظه فقط **یک Process** واقعاً از CPU استفاده می‌کند.

Kernel در بازه‌های زمانی بسیار کوتاه، پردازنده را بین Processها جابه‌جا می‌کند.

به این جابه‌جایی **Context Switch** گفته می‌شود.

```text
Time ─────────────────────────────────────►

CPU
 │
 ├── Process A ──┐
 │               │
 ├── Process B ──┤
 │               │
 ├── Process C ──┤
 │               │
 ├── Process A ──┤
 │               │
 └── Process B ──┘
```

این جابه‌جایی آن‌قدر سریع انجام می‌شود که برای کاربر، اجرای هم‌زمان برنامه‌ها کاملاً طبیعی به نظر می‌رسد.

> 💡 در یک CPU تک‌هسته‌ای، برنامه‌ها واقعاً به‌صورت هم‌زمان روی همان هسته اجرا نمی‌شوند؛ CPU به‌سرعت بین آن‌ها جابه‌جا می‌شود.

---

# ⚙️ Memory Management

مدیریت حافظه نیز یکی از مهم‌ترین وظایف Kernel است.

هر Process تصور می‌کند که حافظه اختصاصی خودش را در اختیار دارد؛ در حالی که Kernel با کمک:

* **Virtual Memory**
* **Memory Management Unit (MMU)**

این توهم را ایجاد می‌کند و دسترسی برنامه‌ها به حافظه را کنترل می‌کند.

```text
Process A                 Process B
┌─────────────┐           ┌─────────────┐
│ Virtual     │           │ Virtual     │
│ Memory      │           │ Memory      │
└──────┬──────┘           └──────┬──────┘
       │                         │
       └──────────┬──────────────┘
                  ▼
                 MMU
                  │
                  ▼
            Physical Memory
                (RAM)
```

این مکانیزم باعث می‌شود برنامه‌ها نتوانند به‌سادگی به حافظه یکدیگر دسترسی پیدا کنند و در نتیجه سیستم **پایداری و Isolation** بیشتری داشته باشد.

---

# ⚙️ User & Root

در پایان، کتاب به مفهوم **User** و **Root** اشاره می‌کند.

در لینوکس، هر Process متعلق به یک **User** است و سطح دسترسی مشخصی دارد.

### 👤 User

یک User معمولی فقط به منابعی که مجوز دسترسی به آن‌ها را دارد، دسترسی خواهد داشت.

### 👑 Root

کاربر **Root** دارای سطح دسترسی بسیار بالایی است و تقریباً به تمام بخش‌های سیستم دسترسی دارد.

به همین دلیل استفاده از Root باید با احتیاط انجام شود، چون یک اشتباه کوچک می‌تواند کل سیستم را تحت تأثیر قرار دهد.

```text
Normal User
    │
    ├── Limited Permissions
    └── Access to permitted resources


Root
    │
    ├── Very High Privileges
    └── Access to most system resources
```

> ⚠️ **Power comes with responsibility.**
>
> هرچه سطح دسترسی بیشتر باشد، یک اشتباه می‌تواند اثر بزرگ‌تری روی سیستم داشته باشد.

---

# 🧩 Putting Everything Together

حالا می‌توانیم تمام مفاهیم این فصل را کنار هم قرار دهیم:

```text
                    USER
                     │
                     ▼
              ┌─────────────┐
              │ Application │
              └──────┬──────┘
                     │
                     │ System Calls
                     ▼
              ┌─────────────┐
              │   KERNEL    │
              │             │
              │ Processes   │
              │ Memory      │
              │ Devices     │
              │ Scheduling  │
              └──────┬──────┘
                     │
                     ▼
              ┌─────────────┐
              │  HARDWARE   │
              │             │
              │ CPU · RAM   │
              │ Disk · NIC  │
              └─────────────┘
```

و در داخل Kernel، Processها توسط Scheduler مدیریت می‌شوند، حافظه توسط Memory Management کنترل می‌شود و ارتباط با Hardware از طریق Kernel و Device Driverها انجام می‌شود.

# ✨ مهم‌ترین نکته این فصل

> ## **قبل از حفظ کردن دستورات لینوکس، باید معماری آن را درک کنیم.**

وقتی بدانیم هر بخش چه مسئولیتی دارد و اجزای سیستم چگونه با هم تعامل می‌کنند، یادگیری مفاهیم پیشرفته‌تر مثل:

* Processها
* Memory
* File System
* Networking
* Device Management
* System Calls

بسیار ساده‌تر و منطقی‌تر خواهد شد.

در واقع هدف این فصل این است که به‌جای حفظ کردن مجموعه‌ای از دستورات، ابتدا یک **تصویر ذهنی درست از Linux** بسازیم.

## 🧠 خلاصه فصل در یک نگاه

| مفهوم              | نقش                                      |

| **Hardware**       | منابع فیزیکی سیستم                       |

## 🎯 Mental Model

اگر بخواهیم کل فصل اول را در چند خط خلاصه کنیم:

```text
                 ┌──────────────┐
                 │   Programs   │
                 │  User Space  │
                 └──────┬───────┘
                        │
                  System Calls
                        │
                        ▼
                 ┌──────────────┐
                 │    Kernel    │
                 │              │
                 │ Processes    │
                 │ Memory       │
                 │ Devices      │
                 │ Scheduling   │
                 └──────┬───────┘
                        │
                        ▼
                 ┌──────────────┐
                 │   Hardware   │
                 │ CPU/RAM/Disk │
                 │ Network/...  │
                 └──────────────┘
```

**برنامه‌ها درخواست می‌دهند → Kernel منابع را مدیریت می‌کند → Hardware کار واقعی را انجام می‌دهد.**

این همان تصویر کلی‌ای است که باید قبل از ورود به جزئیات لینوکس در ذهن داشته باشیم.

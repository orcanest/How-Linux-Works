### ⚙️ **Abstraction**

مهم‌ترین مفهومی که این فصل روی آن تأکید می‌کند **Abstraction** است. 
Abstraction یعنی برای فهم یک سیستم پیچیده ، لازم نیست تمام جزئیات آن را بدانیم. کافی است ابتدا نقش هر بخش را بشناسیم و بعد در صورت نیاز به لایه‌های عمیق‌تر برویم.

فرض کنید می‌خواهید رانندگی کنید. لازم نیست بدانید موتور خودرو دقیقاً چگونه کار می‌کند یا جعبه‌ دنده چه مکانیزمی دارد. کافی است بدانید فرمان، گاز و ترمز چه وظیفه‌ای دارند. اما اگر خودرو دچار مشکل شود، آن‌ وقت باید قدم‌ به‌ قدم به بخش‌ های داخلی نزدیک‌ تر شوید تا علت را پیدا کنید. لینوکس هم دقیقاً با همین دیدگاه طراحی شده است.

🔹 **User Space** :

تمام برنامه‌هایی که ما روزانه با آن‌ها کار می‌کنیم مانند browser , Database , web server , Terminal  و صدها برنامه دیگر.

🔹 **Kernel** :

هسته سیستم‌ عامل که واسطه میان نرم‌افزار و سخت‌افزار است. kernel مدیریت پردازنده، حافظه، دستگاه‌ها و ارتباط برنامه‌ها با سخت‌افزار را بر عهده دارد.

🔹 **Hardware** :

 تمام سخت‌افزار سیستم از CPU و حافظه اصلی (RAM) گرفته تا دیسک و کارت شبکه.

### ⚙️ **Kernel mode vs User mode**

یکی از مهم‌ترین نکات این فصل، تفاوت بین **Kernel Mode** و **User Mode** است. سیستم برای جلوگیری از دسترسی کنترل‌نشده برنامه‌ها به منابع حساس، اجرای کد را به سطوح مختلف دسترسی تقسیم می‌کند.
- **Kernel Mode**

کدی که داخل Kernel Mode اجرا می‌شود، دسترسی کامل به حافظه و پردازنده دارد. به همین دلیل اگر در کرنل خطایی رخ دهد، ممکن است کل سیستم از کار بیفتد.

- **User Mode**

برنامه‌های عادی در User Mode اجرا می‌شوند. هر Process فضای حافظه‌ی مخصوص به خود را دارد؛ بنابراین اگر یک برنامه دچار Crash شود، معمولاً سایر برنامه‌ها و بخش‌های سیستم تحت تأثیر قرار نمی‌گیرند. 

این جداسازی (isolation) یکی از پایه های مهم پایداری (Stability) و امنیت (Secuirty) در لینوکس است ، به صورت ساده :

                 ┌──────────────────────┐
                 │      User Space      │
                 │                      │
                 │ Browser              │
                 │ Database             │
                 │ Terminal             │
                 │ Web Server           │
                 └──────────┬───────────┘
                            │
                       System Call
                            │
                 ┌──────────▼───────────┐
                 │        Kernel        │
                 │                      │
                 │ Process Management   │
                 │ Memory Management    │
                 │ Device Drivers       │
                 │ File Systems         │
                 └──────────┬───────────┘
                            │
                 ┌──────────▼───────────┐
                 │       Hardware       │
                 └──────────────────────┘

### ⚙️ **The four main responsibilities of the kernel**

کرنل وظایف بسیار زیادی دارد، اما در تصویر کلی می‌توان چهار مسئولیت اصلی برای آن در نظر گرفت : 

- 🧵 مدیریت Process ها و زمان‌ بندی اجرای آن‌ها
- 🧠 مدیریت حافظه (Memory Management) و تخصیص منابع حافظه به process ها
- 🔌 مدیریت Device Driver ها و ارتباط با سخت‌ افزار
- 📞 ارائه System Call ها برای ارتباط برنامه‌ها با kernal

در واقع هر بار که یک برنامه بخواهد فایلی را باز کند، data روی دیسک بنویسد یا از شبکه استفاده کند، مستقیماً با سخت‌افزار صحبت نمی‌کند، بلکه از طریق **System Call** از کرنل درخواست انجام این کار را می‌دهد.

```
Application
     │
     │ System Call
     ▼
  Kernel
     │
     ▼
Hardware
```

### ⚙️ **System Call**

دوتا از مهمترین System Call ها ، **()fork** و **()exec** هستند. 

- #### fork()

یک کپی تقریباً یکسان از یک process می سازد. به Peocess اصلی معمولا Parent process و process جدید Child Process گفته می شود.

```
Parent Process
      │
    fork()
      │
      ├──────────────► Parent
      │
      └──────────────► Child
```

- #### exec() 

یک برنامه جدید را بارگذاری کرده و جایگزین برنامه‌ای می‌کند که در Process در حال اجرا بوده است. 
```
Existing Process
       │
      exec()
       │
       ▼
New Program
```
نکته مهم این است که ()exec معمولاً Process جدیدی ایجاد نمی‌کند بلکه برنامه‌ای که در Process اجرا می‌شود را با برنامه جدید جایگزین می‌کند.

مثلاً وقتی دستور ls را در تمرینال می زنید shell یک ()fork انجام می دهد تا یک کپی از خودش بسازد و آن کپی با exec(ls) برنامه ls را اجرا می کند. تقریباً تمام process های یک سیستم لینوکسی همین طور متولد می شوند.

### ⚙️ **Context Switch**

نکته جالب دیگر، نحوه اجرای هم‌زمان برنامه‌هاست. وقتی چندین برنامه را هم‌زمان باز می‌کنید، به نظر می‌رسد همه آن‌ها هم‌زمان در حال اجرا هستند. اما روی یک پردازنده تک‌هسته‌ای، در هر لحظه فقط **یک Process** واقعاً از CPU استفاده می‌کند. 
کرنل در بازه‌ های زمانی بسیار کوتاه، پردازنده را بین Process ها جابه‌ جا می‌کند. فرآیندی که **Context Switch** نام دارد. این جا به‌ جایی آن‌ قدر سریع انجام می‌شود که برای کاربر، اجرای هم‌ زمان برنامه‌ ها کاملاً طبیعی به نظر می‌رسد.
```
Time ─────────────────────────────────────►

CPU
 │
 ├── Process A ──┐
 │               │
 ├── Process B ──┤
 │               │
 ├── Process C ──┤
 │               │
 ├── Process A ──┤
 │               │
 └── Process B ──┘
```
> 💡 در یک CPU تک‌هسته‌ای، برنامه‌ها واقعاً به‌صورت هم‌زمان روی همان هسته اجرا نمی‌شوند؛ CPU به‌سرعت بین آن‌ها جابه‌جا می‌شود.

### ⚙️ **Memory Management**

مدیریت حافظه نیز یکی از مهم‌ترین وظایف kernel است. هر Process تصور می‌کند که حافظه اختصاصی خودش را در اختیار دارد، در حالی که کرنل با کمک **Virtual Memory** و **Memory Management Unit (MMU)** این توهم را ایجاد می‌کند و دسترسی برنامه‌ها به حافظه را کنترل می‌کند. این مکانیزم باعث می‌شود برنامه‌ها نتوانند به حافظه یکدیگر دسترسی پیدا کنند و سیستم پایداری بیشتری داشته باشد. 
```
Process A                 Process B
┌─────────────┐           ┌─────────────┐
│ Virtual     │           │ Virtual     │
│ Memory      │           │ Memory      │
└──────┬──────┘           └──────┬──────┘
       │                         │
       └──────────┬──────────────┘
                  ▼
                 MMU
                  │
                  ▼
            Physical Memory
                (RAM)
```

### ⚙️ **User & Root**

در پایان، کتاب به مفهوم **User** و **Root** اشاره می‌کند.  در لینوکس هر Process متعلق به یک User است و سطح دسترسی مشخصی دارد. تنها کاربر **Root** تقریباً به تمام بخش‌ های سیستم دسترسی دارد. به همین دلیل، استفاده از Root باید با احتیاط انجام شود، چون یک اشتباه کوچک می‌تواند کل سیستم را تحت تأثیر قرار دهد. 
```
Normal User
    │
    ├── Limited Permissions
    └── Access to permitted resources


Root
    │
    ├── Very High Privileges
    └── Access to most system resources
```

> ⚠️ هرچه سطح دسترسی بیشتر باشد، یک اشتباه می‌تواند اثر بزرگ‌تری روی سیستم داشته باشد.

### 🧩 Putting Everything Together

حالا می‌توانیم تمام مفاهیم این فصل را کنار هم قرار دهیم: 
```
                    USER
                     │
                     ▼
              ┌─────────────┐
              │ Application │
              └──────┬──────┘
                     │
                     │ System Calls
                     ▼
              ┌─────────────┐
              │   KERNEL    │
              │             │
              │ Processes   │
              │ Memory      │
              │ Devices     │
              │ Scheduling  │
              └──────┬──────┘
                     │
                     ▼
              ┌─────────────┐
              │  HARDWARE   │
              │             │
              │ CPU · RAM   │
              │ Disk · NIC  │
              └─────────────┘
```

در داخل کرنل ، Process ها توسط Scheduler مدیریت می‌شوند، Memory توسط Memory Management کنترل می‌شود و ارتباط با Hardware از طریق Kernel و Device Driver ها انجام می‌شود.
